# Mission tools

Positions are metres north/east of the search centre; altitude is metres above the named drone's home. IDs are exactly `Drone1`–`Drone4`. **S** means an explicit approval in Supervised mode, direct execution in Autonomous mode. **None** means no flight approval. All results contain resulting state or a precise error; a decline returns `Operator declined`. The same handlers serve agent calls and operator controls.

Twenty-five functions are registered. `open_feed` remains catalogue only. Flight acceptance requires actual MAVLink state; a command acknowledgement does not mean a destination has been reached. Ground-team delivery remains `sent` until the receiving page explicitly acknowledges; opening the page does not acknowledge it.

The flight band is 10–100 m above home, speed 0.5–15 m/s, and minimum route separation is 3.5 m. World bounds come from `world/cosys/world.json`; MAVLink fence read-back, including the southern launch corridor, controls the map and final geometric checks. Arming and failsafe checks remain enabled.

The public landmark schema requires finite nonnegative `heightM`. Positive heights require polygon footprints; trail, road, creek and pond heights are zero. Every route and re-look leg requires continuous 10 m clearance above terrain plus height inside polygon footprints. Takeoff, landing and RTL ground columns reject raised footprints. Missing catalogue data prevents planning and clearance-checked flight; no empty catalogue is substituted. See the [schema](../../world/cosys/README.md#public-landmarks) and [search safety contract](../search/README.md#planning-and-flight).

The Sierra prior domain is `temperate_mountainous` for dementia and terrain-pooled `temperate` for typically developing children. Other profiles, including hikers, lack a verified local table and fail explicitly. `define_search_area` requires the recorded profile's domain; selecting an Australian hiker table is unsupported. The dementia feature mixture is provisional, retains unresolved Brush/Field background and requires its documented geometry. Wonder reports its limitations without inventing numeric water preference or clue movement updates.

## Wonder loop and measurement

The service uses `muse-wonder-1.0`, low reasoning, flat Responses function definitions and `store=true`. Each operator request starts a new response chain with the briefing, the five most recent messages (bounded to 1,200 characters each) and up to eight recent operator actions. Within that request, tool results use `function_call_output` with the original `call_id` and `previous_response_id`, without a new user message or repeated briefing. Short safety instructions and new operator actions accompany continuations. The loop has a twelve-turn bound; errors never trigger a retry.

Flight results contain aircraft identity, mode, armed/landed state, north/east, altitude above home, mission progress and the acknowledged command. `get_fleet` adds link age/health to one compact row per drone. `get_drone` adds battery, GPS, EKF, waypoints and the last five status texts. Only `get_mission` provides fence summaries; raw fences and telemetry histories remain in the browser stream. Each model response logs `usage.input_tokens`, output tokens and request-body bytes. Credential-free request/response traces remain beside mission events.

Verified against Meta's primary [Responses protocol](https://dev.meta.ai/docs/protocols/responses) and [tool-calling documentation](https://dev.meta.ai/docs/tool-calling). The map tool uses `strict=false` with optional selectors so point and area requests need no unused drone ID. Code enforces the exact fields for each target. The service validates every argument itself; Meta's `strict` flag validates schema definitions rather than guaranteeing generated argument correctness.

Run `.venv-cosys/bin/python -m mission_planner.agents.bench_tools --output .local/evidence/search/<new-run>` for 52 fresh-conversation selection cases. This sends real Wonder requests and does not execute aircraft commands. Cases include exact/ambiguous/unknown place resolution, deterministic directions and sourced Sierra domain selection, plus flight/search tools, evidence review, operator-only resolution, re-look approval, lower visual-only looks, uncalibrated evidence, recorded provenance, terminal frame failures and receiving-page acknowledgement. Scores compare unordered tool calls and JSON arguments; numerically equal JSON numbers match. No-tool cases require zero calls; prose is inspected separately. Each case preserves credential-free request/response traces, HTTP status, request-body bytes, latency and token usage. Outputs must use a new directory. A failed request is recorded once and the benchmark continues with the next distinct case. `--first-case N` selects an explicit unattempted suffix; it is not a retry mechanism.

The accepted [flight-tool baseline](../measurements/gcs-tools.json) remains preserved. Commander selection results and inspection are recorded in [commander.json](../measurements/commander.json), with raw requests and responses in the named evidence directory. Every miss remains in the measurement. Place results are in [places.json](../measurements/places.json).

Search contracts, statistical sources and camera-source semantics are documented in [search](../search/README.md). The operator explicitly selects Live coupled captures or a recorded manifest. Recorded frames preserve the original camera position, drone and capture time. Only the exact calibrated person configuration earns detection likelihood or negative credit; briefing appearance/clue prompts remain uncalibrated leads. SAM/Glimmer scores do not establish identity. The evidence card exposes the provisional probability change and optional Glimmer description labelled Model opinion.
